Update 2026-07-16 (later same day) — percentage formatting fix:
  Root cause found: build_ids_result_report.py captured each row's cell STYLE
  (font/border/fill/protection) from the DK template but dropped the NUMBER
  FORMAT when writing the "Score (One hundred perfect score conversion)" row
  (dealer %) and the "Ave. %" column — both ended up "General" format, so a
  score of 0.739 displayed as the raw decimal "0.73" instead of "73.9%".
  Cells were also locked (though sheet protection itself was confirmed OFF
  via Excel COM — ProtectContents=False on every sheet/workbook).

  Fix applied in build_ids_result_report.py: percentage cells now get an
  explicit "0.0%" number format and are explicitly unlocked. All 13 country
  reports were rebuilt with the fix; layout QA and logic check both re-run
  and still pass 13/13, 0 issues.

  combine_evaluation_result_reports.py was also rewritten to read source
  values via Excel COM (win32com) instead of xlrd, because the Score % and
  Ave. % cells are live formulas with no cached value in the raw .xls —
  xlrd (no formula engine) read them as blank. Opening via Excel resolves
  the formulas correctly before copying into the combined workbook, which
  now also carries the "0.0%" format on those cells.

  Not changed: the `_delta/*_Delta.xlsx` files remain plain decimals (e.g.
  0.0294) — these are an internal QA aid, explicitly excluded from review/
  export, so left as-is. Rankings\*.xlsx files already store percentages
  on a 0-100 scale (e.g. 95.71, not 0.9571) so were not affected by this bug.
