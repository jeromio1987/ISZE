What is missing, and what it would unlock

To name the customer behind a delayed warehouse line, one column is enough. IML knows which sold-to each purchase order is raised for - the warehouse document simply does not carry it. Everything below is what that would unlock, in the order I would ask for it.

MissingWhat it would answerWho has it
Destination customer or sold-to on the warehouse extractWhich distributor is behind each delayed line, and therefore which of the 1,090 lines over 30 days belong to whom. This is the whole answer and nothing else closes it.IML / ISZJ
Actual dispatch date per lineWhich lines really left the building, so "ready for shipment" can be separated from "finished and forgotten".IML warehouse
Actual arrival date per lineHow long a line was on the water. Without it, time underway cannot be measured from any file we hold, including Power BI.IML / freight forwarder
Fill rate for the distributors that do not reportUMI, Germany (ISD), Benelux (IBX), Denmark, Cyprus and Greece have no current value. They are named here rather than filled in.ISZE KPI cycle
Back-order lines for the distributors that do not reportMalta, Cyprus and Greece have no current back-order count, so their delay cannot be ranked.ISZE KPI cycle

What I checked and did not find

  • Customer order number against IML order number: zero matches.
  • Customer reference against IML order number: zero matches.
  • Part number against the warehouse file: it matches, but a part is not a customer.
  • Dispatch and arrival dates: Invoice, Shipped and ETD are empty on all 2,102 rows, so this file cannot show a voyage at all.
  • PBI will not close it either: Power BI reads the same SAP, and SAP records billing, not shipping.
